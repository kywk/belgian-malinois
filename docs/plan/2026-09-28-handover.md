## 為什麼沒有做 Stage 2 / Stage 3（測試網與 form-service 整併）

原計畫的下一步是 Stage 2（Flyway + Testcontainers，7 人日）與 Stage 3（form-service 整併，3 人日）。兩者都**刻意沒做**：

- **Stage 2 的產出本身就是測試**。在沒有 javac 的環境寫測試，等於產出一批無法執行、無法驗證的測試碼 —— 比沒有測試更糟，因為它會製造虛假的信心，而且必然讓 build 壞掉。
- **Stage 3 要搬 11 個檔案、新增第三個 persistence unit**。這正是最需要編譯器的那種變更。提交一個半成品的合併會讓 repo 處於比現在更差的狀態。
- Flyway baseline migration 需要對著真實 MSSQL 驗證，無 docker 時只能靠猜 —— 錯誤的 migration 比沒有 migration 危險得多。

同理，我也**沒有動用多個 worktree 並行開發** —— 沒有編譯器時，並行只會更快地產出更多無法驗證的程式碼。改為投入在「獨立閱讀審查」上，那是這個環境下唯一有效的驗證替代品。
